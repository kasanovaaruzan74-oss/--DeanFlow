# DeanFlow жобасына арналған зертханалық жұмыстар

Бұл нұсқаулық жеті зертханалық жұмыстың нәтижесін DeanFlow доменіне сәйкестендіреді. Негізгі өнім ASP.NET Core MVC және SQL Server технологияларын қолданады; тапсырмадағы Python тақырыптарын көрсету үшін бөлек `labs/deanflow-demo/` модулі берілген. Ол FastAPI, SQLModel, Streamlit, SQLite, Docker Compose және pytest-ті пайдаланады. Осылайша дайын веб-жобаның архитектурасы сақталады, ал зертханада талап етілген Python коды бөлек іске қосылып, көрсетіледі.

Демо модулі оқу деректерімен ғана жұмыс істейді. Ол негізгі DeanFlow SQL Server базасына қосылмайды және аутентификацияны іске асырмайды. Сондықтан оған нақты студенттер мен қызметкерлердің деректерін енгізбеңіз.

## №1 зертханалық жұмыс — жүйені жобалау және Git

**Мақсаты.** DeanFlow-дың деректер моделін ER диаграммасында көрсету, Python демо ортасын дайындау және жобаның кодын Git арқылы басқару.

**Нәтижесі.** [ER диаграммасы](diagrams/deanflow-er.png) негізгі он бір кестені, PK/FK өрістерін және 1:N байланыстарын көрсетеді. [Өңделетін SVG нұсқасы](diagrams/deanflow-er.svg) да берілген. Негізгі схема `Data/Entities.cs` пен `Data/DeanFlowDbContext.cs` файлдарынан алынған; шағын оқу схемасы `models.py` ішінде қайталанады.

**Орындау реті.**

1. DeanFlow шешетін мәселені сипаттаңыз: құжат тіркеу, іздеу, орындаушы тағайындау, мерзім бақылау және келісу.
2. Диаграммадағы `users`, `departments`, `documents`, анықтамалық кестелер және құжатқа тәуелді жазбалардың байланысын түсіндіріңіз.
3. `labs/deanflow-demo/` ішінде Python 3.11 виртуалды ортасын құрып, `requirements.txt` тәуелділіктерін орнатыңыз.
4. `.gitignore` файлында виртуалды орта, `.env`, SQLite файлдары және кэш каталогтары бар екенін тексеріңіз.
5. Тәжірибеде негізгі тармаққа тікелей өзгертулер енгізбей, `feature/lab-01-er-git` сияқты тармақта жұмыс істеп, өзгерістерді тексеруден кейін біріктіріңіз.

AI көмекшісіне берілетін қысқа сұрау: *«DeanFlow — деканат құжат айналымы жүйесі. `Data/Entities.cs` және `Data/DeanFlowDbContext.cs` негізінде пайдаланушылар, бөлімдер, құжаттар, мәртебелер, орындаушылар, келісімдер, тарих, пікірлер және тіркемелер үшін PK/FK пен 1:N байланыстарын белгілейтін қазақша ER диаграммасын ұсын. Барлық кестелерді бастапқы кодпен салыстыр.»*

**Түсіндіру.** `venv` Python кітапханаларын осы демоға оқшаулайды. `.gitignore` орындалатын ортаны, жергілікті дерекқорды және құпия `.env` файлдарын Git-ке кіргізбейді. `git commit` өзгерісті жергілікті репозиторий тарихына тіркейді; `git push` оны қашықтағы серверге жібереді. `main` тармағына бірден жазбай, жеке тармақта жұмыс істеу тексеруге және кері қайтаруға мүмкіндік береді. AI жасаған кодты модельдермен және іске қосылған жүйемен салыстырмай көшірмеңіз.

## №2 зертханалық жұмыс — ORM модельдері және бастапқы деректер

**Мақсаты.** ER кестелерін Python ORM кластарымен бейнелеп, кілттер мен объектілік байланыстарды орнату, SQLite базасын құру және демо деректерін енгізу.

**Файлдар.** `app/database/models.py` — `Role`, `Department`, `AppUser`, `DocumentType`, `DocumentStatus`, `DeanDocument`, `ExecutorAssignment`, `DocumentApproval`, `DocumentHistoryEntry`, `DocumentComment`, `DocumentAttachment`; `db.py` — engine және сессия; `seed.py` — үлгі деректер.

**Орындау реті.**

```powershell
cd labs/deanflow-demo
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m app.database.seed
```

Скрипт `create_all` арқылы кестелерді бастапқы рет құрып, рөлдер, бөлімдер, құжат түрлері, мәртебелер, пайдаланушылар, құжаттар, тапсырмалар, пікірлер, тіркемелер және журнал жазбаларын қосады. Қайта іске қосқанда бірдей үлгі жазбалары қайталанбайды. `deanflow_labs.db` Git-ке кірмейді. Негізгі DeanFlow базасына `EnsureCreated`, көшіру немесе бастапқы дерек енгізу жасалмайды.

**Түсіндіру.** ORM Python класын реляциялық кестемен сәйкестендіреді. `document_type_id` — дерекқорда сақталатын FK; `document_type` — бағдарлама ішінде байланысқан объектіні оқуға арналған `Relationship`. Seed data бос базаға демо жасап, API/UI-ді тексеруге мүмкіндік береді. SQLModel `echo=True` орнына SQL журналын нақты қажет кезде қосуға болады; әдепкіде сұраулар консольге шығарылмайды. Код Git-ке жіберіледі, ал жергілікті `.db` дерекқор файлы `.gitignore` арқылы репозиторийден тыс қалады.

## №3 зертханалық жұмыс — FastAPI арқылы REST API

**Мақсаты.** HTTP маршруттарын, кіріс деректерді валидациялауды, дерекқор сессиясын dependency арқылы беруді және OpenAPI құжаттамасын көрсету.

**Іске қосу.**

```powershell
cd labs/deanflow-demo
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload
```

`http://127.0.0.1:8000/docs` Swagger UI бетін ашады. `GET /documents` тізімді береді; `GET /documents/{id}` бір құжатты оқиды; `POST /documents` жаңа құжат жасайды. `documents.py` ішіндегі `Depends(get_session)` әр сұрауға жеке SQLModel сессиясын беріп, сұрау біткенде жабады. FastAPI сұрауды `DocumentCreate` схемасымен тексереді: мысалы, тым қысқа тақырып `422` қайтарады. Табылмаған нөмірге `404` беріледі.

**Демонстрация.** Swagger-де алдымен `GET /documents` басып үлгі тізімді оқыңыз; кейін `POST /documents` үшін дұрыс дерек жіберіңіз; соңында үш таңбадан қысқа тақырыппен `POST` жасап, `422` нәтижесін көрсетіңіз.

## №4 зертханалық жұмыс — CRUD, жаңарту, жою және сүзу

| HTTP әдісі | Маршрут | Нәтиже |
| --- | --- | --- |
| `GET` | `/documents?search=өтініш&status_code=IN_PROGRESS` | Іздеу және сүзу |
| `GET` | `/documents/{id}` | Бір құжатты оқу |
| `POST` | `/documents` | Құжат құру, `201` |
| `PATCH` | `/documents/{id}` | Тек жіберілген өрістерді өзгерту |
| `DELETE` | `/documents/{id}` | Жазбаны жою, `204` |

**Түсіндіру.** `PUT` әдетте объектінің толық бейнесін алмастырады; `PATCH` тек өзгертілетін өрістерді жібереді. Құжат идентификаторы табылмаса, оқу, жаңарту және жою `404` қайтарады. Сүзу жолдары `select()` өрнегінде параметрленеді; SQL мәтініне пайдаланушы енгізген жол тікелей жалғанбайды. Жою алдында объект тексеріледі, сондықтан API «жойылды» деп жалған жауап бермейді.

**Демонстрация.** Swagger-де бір тақырыппен құжат құрып, `GET` арқылы табыңыз; `PATCH` арқылы тек мәртебені не тақырыпты өзгертіп, қалған өрістер сақталғанын көрсетіңіз; `DELETE` жасап, сол ID-ге қайта `GET` жібергенде `404` болатынын тексеріңіз. `GET /documents?search=...` сүзгісін де көрсетіңіз.

## №5 зертханалық жұмыс — Streamlit веб-интерфейсі

**Мақсаты.** API деректерін браузерге шығару, іздеу сүзгілерін жасау және жаңа құжатты форма арқылы жіберу.

Бірінші терминалда FastAPI серверін, екінші терминалда Streamlit-ті іске қосыңыз:

```powershell
streamlit run app/frontend/ui.py
```

`http://localhost:8501` бетінде құжаттар кестесі, тіркеу нөмірі/тақырып іздэх талабы, мәртебе және бағыт сүзгілері, жаңа құжат формасы бар. Python `requests` кітапханасы деректерді HTTP және JSON арқылы API-ге жеткізеді. Іздеу мәндері `params=` арқылы URL query параметріне, жаңа құжат өрістері `json=` арқылы POST body бөлігіне беріледі. Қосылым үзілсе, UI қате туралы қазақша хабарлама көрсетеді.

**Демонстрация.** Тізімнен «өтініш» деп іздеңіз; мәртебені ауыстырып, кестенің өзгергенін көрсетіңіз; жаңа құжатты тіркеп, оның жаңа нөмірмен тізімге қосылғанын растаңыз.

## №6 зертханалық жұмыс — Docker және Docker Compose

**Мақсаты.** Backend және frontend орталарын контейнерге жинау, ішкі желі арқылы байланыстыру және SQLite деректерін контейнер қайта құрылғанда сақтау.

```powershell
cd labs/deanflow-demo
docker compose up --build
```

`Dockerfile` API кескінін, `Dockerfile.frontend` интерфейс кескінін құрады. Compose сервер мен интерфейс қызметтерін бір желіде іске қосып, `BACKEND_URL=http://backend:8000` орнатады. Compose желісіндегі DNS `backend` атауын дұрыс контейнерге бағыттайды; интерфейс контейнеріндегі `localhost` серверді емес, сол контейнердің өзін білдіреді. Сервердің дайындық тексеруі UI-ді содан кейін іске қосады. SQLite файлы `deanflow-demo-data` томында сақталады.

`docker compose down` қызметтерді тоқтатады, бірақ томдағы деректерді қалдырады. `docker compose down -v` деректер томын да жояды. `.dockerignore` виртуалды ортаны, `.env`, SQLite және кэш файлдарын образға кіргізбейді.

## №7 зертханалық жұмыс — интеграциялық тесттер және қорғау

**Мақсаты.** API-дің негізгі сценарийлерін автоматты тексеріп, жүйенің шекараларын түсінікті түрде көрсету.

```powershell
cd labs/deanflow-demo
pytest -q
```

`tests/test_documents_api.py` тізім оқу, құжат құру, жарамсыз сұрауды қабылдамау, `PATCH` пен `DELETE`, белгісіз SQL бөлігі ретінде берілген іздеуді қауіпсіз өңдеу сценарийлерін тексереді. `TestClient` қосымша API-іне тікелей HTTP сұрау жасайды, бөлек Uvicorn серверін іске қосу қажет емес. Нұсқаулықтағы `httpx` кітапханасы HTTP клиентінің міндетін атқарады; осы ортадағы Starlette `TestClient` ескірген ескертусіз жұмыс істеуі үшін `httpx2` қолданады. Әр тест уақытша SQLite файлында іске қосылып, негізгі не seed дерекқорына әсер етпейді.

**Қорғау реті.**

1. DeanFlow бизнес-мәселесін және рөлдер бойынша қолжетімділікті қысқаша сипаттаңыз.
2. ER диаграммасында `documents` орталық кестесі, оның анықтамалықтары және тәуелді жазбаларын көрсетіңіз.
3. `models.py` ішіндегі FK пен `Relationship` айырмасын мысалмен түсіндіріңіз.
4. Swagger-де сүзу, құру, жартылай жаңарту және табылмаған ID мысалын көрсетіңіз.
5. Streamlit формасынан API мен SQLite-қа өтетін сұрау жолын көрсетіңіз.
6. `docker compose up --build` арқылы екі қызметті іске қосып, `pytest -q` нәтижесін көрсетіңіз.
7. AI ұсынған кодты қарап, валидация, 404/422 өңдеу, параметрленген SQL және құпияны сақтау ережелерін тексергеніңізді түсіндіріңіз.

## Қорғауға арналған қысқа жауаптар

### №1 сұрақтар

1. **`venv` не үшін керек?** Ол кітапхана нұсқаларын әр жобаға бөлек сақтайды. Онсыз бір жобаға орнатылған пакет басқа жобаның талабымен қайшылыққа келуі мүмкін.
2. **`.gitignore` неге қажет?** Жергілікті орта, база және құпия баптаулар код репозиторийіне түспеуі үшін. `venv`, `.env` және `.db` файлдары ортаға тәуелді не дерек сақтайды.
3. **AI көмекшісінің рөлі мен тәуекелі?** Ол үлгі кодты жылдам ұсынады; бірақ қате байланыс, әлсіз рұқсат немесе қауіпсіз емес сұрау ұсынуы мүмкін. Кодты іске қосып, деректер моделіне салыстырып тексеру керек.
4. **Git тармағы неге қажет?** Жеке тармақта өзгерістерді негізгі нұсқадан бөлек тексеруге болады. `main` тұрақты және көрсетілетін нұсқа болып қалады.
5. **`commit` пен `push` айырмасы қандай?** `commit` жергілікті тарихқа жазады, `push` сол commit-терді қашықтағы Git серверіне жібереді.

### №2 сұрақтар

1. **ORM деген не?** Python кластары мен SQL кестелерін сәйкестендіретін қабат; SQL-ді әр операция үшін қолмен құру қажеттігін азайтады.
2. **FK мен `Relationship` айырмасы қандай?** FK — кестеде сақталатын сандық кілт; `Relationship` — сол FK арқылы байланысқан Python объектісі.
3. **Seed data не үшін керек?** Бос базада API, UI және сценарийлерді бірден көрсетуге болатын нақты мысалдар болмайды.
4. **`echo=True` нені көрсетеді?** ORM жіберген SQL сұрауларын консольге шығарып, сұрауды түсінуге көмектеседі. Өндірісте қажетсіз дерек пен шу болмауы үшін сөндіріледі.
5. **Неге `.db` жіберілмейді, ал модельдер жіберіледі?** Модель — қайталанатын код; SQLite файлы жергілікті күй мен оқу деректерін сақтайды, көлемі үлкеюі немесе дерек қалдықтарын қамтуы мүмкін.

### №3 сұрақтар

1. **REST API деген не?** HTTP арқылы ресурстарға стандартталған әдістермен қатынау тәсілі. `GET` оқиды, `POST` жаңа ресурс жасайды.
2. **Pydantic қандай міндет атқарады?** Сұрау өрістерінің түрі мен шектеулерін тексеріп, жарамсыз дерекке автоматты `422` қайтарады.
3. **Dependency Injection не үшін керек?** `Depends(get_session)` дерекқор сессиясын әр маршрутқа беріп, сұрау аяқталғанда жабады. Осы тәсіл барлық сұрауға бір ортақ сессияны бөліп қолданудан сақтайды.
4. **Swagger қолмен жазыла ма?** Жоқ. FastAPI маршрут пен схемаға қарап OpenAPI құжаттамасын және Swagger UI-ді өзі құрады.
5. **`422` нені білдіреді?** Сұраудың JSON құрылымы танылды, бірақ оның мәндері схема талаптарына сай емес.

### №4 сұрақтар

1. **`PUT` пен `PATCH` айырмасы?** `PUT` толық объектіні алмастыруға арналған; `PATCH` тек көрсетілген өрістерді өзгертеді.
2. **Query параметрі деген не?** URL соңындағы сүзгі мәні, мысалы `/documents?search=өтініш`. Ол сұраудың қай бөлігін оқу керегін көрсетеді.
3. **SQL инъекциясынан қалай қорғанамыз?** Іздеу мәтіні SQL командасына жалғанбайды; ORM оны bind параметрі ретінде жібереді.
4. **Неге жоймас бұрын ID табамыз?** Нақты объект бар-жоғын анықтап, жоқ болса `404` қайтарамыз; қате «сәтті жойылды» жауабын бермейміз.
5. **CRUD нені білдіреді?** Create — `POST`, Read — `GET`, Update — `PATCH`/`PUT`, Delete — `DELETE`.

### №5 сұрақтар

1. **Streamlit пен FastAPI қалай сөйлеседі?** Streamlit `requests` арқылы HTTP сұрау жібереді, JSON жауап алады. Интерфейс пен API браузерге бір бет болып көрінгенімен, олар бөлек қызмет.
2. **`requests` ішіндегі `params` пен `json` айырмасы?** `params` URL сұрау параметрлерін жасайды; `json` JSON body жіберіп, POST құру деректерін тасымалдайды.
3. **API тоқтаса UI не көрсетеді?** Сұрау timeout/қосылым қатесін ұстап, қазақша түсіндірме мен API мекенжайын көрсетеді.
4. **Streamlit неге кодты қайта орындайды?** Widget өзгергенде Streamlit скриптті қайта іске қосып, жаңа күймен интерфейсті сызады. Қажет мәндерді `session_state` ішінде сақтауға болады.
5. **Streamlit-тің шектеуі қандай?** Демо мен дерекке бағытталған интерфейсті тез құрады; күрделі клиенттік әрекеттер мен толық пиксельдік дизайн үшін React/Vue сияқты тәсілдер икемдірек.

### №6 сұрақтар

1. **Контейнер мен виртуалды машина айырмасы?** Контейнер хост ядросын бөлісіп, қолданба мен тәуелділіктерді оқшаулайды; виртуалды машина толық қонақ операциялық жүйені іске қосады.
2. **`WORKDIR`, `COPY`, `EXPOSE`, `CMD` не істейді?** Жұмыс қалтасын таңдайды; файлдарды образға көшіреді; контейнердің қызмет портын құжаттайды; контейнер бастағанда орындалатын команданы анықтайды.
3. **`RUN` мен `CMD` айырмасы?** `RUN` образ құру кезінде орындалып, қабат жасайды; `CMD` контейнер іске қосылғанда негізгі процесті бастайды.
4. **`.dockerignore` не үшін?** Артық файлдарды құрылыс контекстінен алып тастап, контейнер кескінін кішірейтеді және жергілікті құпия не деректерді көшірмеуге көмектеседі.
5. **Compose `backend` атауын қалай табады?** Compose ішкі желісінде DNS қызмет атауын контейнер IP-мекенжайына шешеді; IP өзгерсе де атау тұрақты қалады.
6. **`docker compose down` соңында SQLite дерегі не болады?** Дерек атаулы томда болғандықтан сақталады. `down -v` томды да өшіреді.

### №7 сұрақтар

1. **Автоматты тест не үшін керек?** Өзгеріс бұрын дұрыс жұмыс істеген маршрутты бұзбағанын қайталап тексереді; өскен жүйеде қолмен тексеруден жылдам.
2. **FastAPI `TestClient` үшін сервер керек пе?** Жоқ. Ол қосымшаны тікелей шақырып, HTTP сұраулары мен жауаптарын тексереді.
3. **`httpx` не үшін керек?** TestClient HTTP клиент мүмкіндіктерін қолдану үшін; интеграциялық тесттерде сұраулар құрады.
4. **AI қауіпсіздік ревьюінің шегі қандай?** Ол ықтимал қатені нұсқай алады, бірақ қорғаныс дәлелі емес. Ұсынысты код, рұқсат саясаты және тест арқылы тексеру керек.
5. **Регрессиялық тест деген не?** Бұрын жұмыс істеген мүмкіндіктердің жаңа өзгерістен кейін де дұрыс екенін тексеру. Мұнда GET/POST/PATCH/DELETE маршруттары қайта-қайта автоматты тексеріледі.
